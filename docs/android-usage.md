# 安卓真机使用说明

## 2026-10-09：桌面 USB 流程的观演人选择

- 默认按订单确认页上完整观演人列表的顺序选择：1 张选第 1 人、2 张选前 2 人，以此类推。第一人不等同于账号本人，请自行确认列表顺序。
- 切换到自定义后，可提前逐行填写手机保存的姓名，或从已读取的确认页名单勾选。自定义人数必须与张数相同；同名时使用包含证件类型和脱敏号码的完整显示标识，不输入完整证件号码。
- 只在原生页面完整识别、目标订单核对一致后逐人勾选。先取消非目标人，再选目标人，每次点击后核对结果。目标不可选、人数不足、标识重复、列表不完整或中途顺序变化时停止，不跳过、不替换。
- 名单变化会使旧准备失效。关闭自动提交时，选好观演人后仍停在确认页；启用自动提交才会在全部核对通过后提交一次，到支付宝停止。姓名和脱敏标识只保存在当前运行内存，不写入步骤日志或设置存储。
- 这是现有 Mac USB 执行器的能力，不是手机验证 APK 的独立执行能力。本轮未提交真实订单；手机只读复核遇到前台/锁屏限制，因此新增自动勾选尚未完成真机验收。

更新：2026-10-08（北京时间）。已支持自动读取场次、票档，以及可勾选的自动提交订单、跳转支付宝后暂停。10 月 3 日的桌面包验收已到支付宝收银台，未付款；10 月 8 日优化版验证了读取与未开售待命，没有重复提交订单。详情见 [方案与验收记录](android-device-design.md)。

## 本地 APK 重构进行中

本轮新增独立的 `android-companion/` 手机端可行性验证工程。它与现有桌面执行器分开，先验证系统无障碍读取、用户授权截图和离线中文识别；验证版本不提供购票或提交接口。正式手机端执行、观演人自定义和持续捡漏须在真机能力验证通过后接入，不能把验证 APK 当作完整抢票版本。

现有桌面界面暂时保留。浏览器与桌面尚未完成同执行器对比，不宣称网页化能提速。

### 真实选票页适配状态

用户确认真实页面已同时显示场次和票价，但手机无障碍读取到的控件标识尚未匹配旧版适配。已确认读取的是活动的大麦窗口，并读到了场次、票档文字标记；接下来需核对新版控件结构，不能凭这些计数直接开始点击。`native_audit` 只在手机本地开启一次性授权后读取原生布局，不截图、不 OCR、不下单；详情见 [只读核对记录](android-native-audit-2026-10-08.json)。目前请继续保留 USB 连接，尚无“下发后断线独立抢票”的可用版本。

### 可重复的只读性能基线

使用 `uv run --offline tools/android/benchmark.py --serial <设备序列号> --samples 30`，在手机保持同一演出详情或选票页时测量。工具只读取，不点击、不刷新库存、不提交；页面目标变化或出现阻断提示时本组终止，截图和页面文字不写入报告。第一个样本单列，热样本按 OCR 缓存命中、未命中和纯节点路径分组。

2026-10-08 在 SEA-AL10／Android API 29／大麦 9.0.35 的同一真实演出详情页测量：本进程首次读取 **10,276.06 ms**，其中 OCR **7,527.8 ms**；之后 30 次热读取全部命中 OCR 缓存，中位 **417.54 ms**，第 95 百分位 **690.63 ms**。页面树中位 **212.0 ms**，截图中位 **154.75 ms**。这是现有 Mac 执行路径的基线，不是手机 APK 的成绩、网页对比或下单速度。原始耗时与方法见 [脱敏基线数据](android-baseline-2026-10-08.json)。

## 2026-10-08 续作：配对与提交保护集成

手机端仍是**只读可行性验证 APK**，不是完整购票执行器。已安装到当前 SEA-AL10（Android API 29），重新确认大麦包名为 `cn.damai`。无障碍服务由用户手动开启，录屏同样必须手动授权。

- 按用户实际操作反馈，把手抄 48 位密钥改成手机主动生成的 **8 位一次性配对码**。120 秒有效，5 次有效格式的失败尝试后失效，成功兑换即消费，重新生成会立即作废旧码。长密钥仅保留在进程内存，不输出到聊天、命令行参数或日志。
- 电脑验证工具已对齐 APK 的嵌套 `summary` 协议；保留结果标记、原生节点/截图/OCR 耗时与固定错误码，丢弃页面文字、观演人和密钥。异步识别只轮询状态，不重复发起检查。成功配对后增加单独的页面准备提示，避免配对时仍停在首页就开始检查。
- 新增单列首次样本及 30 次热读页的测量入口。手机原生耗时与包含转发/轮询的 USB 往返耗时分别报告；APK 当前不返回页面身份，因此只能由操作者保持页面不变，工具仅能检测页面类别变化，不能据此声称精确同页验证或与旧执行器等价提速。
- 桌面提交保护统一到 `com.tickets/android-submissions`。同时锁定并检查旧 `Tickets/android` 目录，新提交意图必须先在两处持久化成功，才允许发出提交点击。损坏、写入失败或两处出现不同的未解除记录，均保持禁止执行；不自动删除、不按时间戳丢弃旧记录。
- 解除限制需要用户先核对手机订单，再明确确认对应的 32 位提交记录标识；已运行或有设备操作时不能解除。此保护不宣称能抵御手动删库、任意自定义目录或未升级的旧驱动。使用新版前应关闭并重启旧桌面/命令行驱动。

引导式验证命令：`python3 tools/android/companion_probe.py --serial <设备序列号> --action inspect --samples 30 --dialog`。`--dialog` 在 macOS 本机输入框中接收短码；其他系统可省略它，使用不回显的终端输入。命令只支持验证接口，不提供购票点击。

本轮已观测到短码配对成功、合成页节点可读及测试按钮计数增加。原截图时间戳问题修复后，后续复测完成合成页截图和 OCR，30 次热样本全部完成：OCR 中位 **331.5 ms**、P95 **384 ms**，USB 总往返中位约 **587 ms**。单独检查识别到 26 个文字块及 1 个中文候选；用户开启合成页受保护开关后，程序在 OCR 前安全停止。早先一次黑屏的原因仍未确认。**合成页通过不等于真实选票页、识别准确率或手机本地购票验收通过，也不能据此宣称比旧版提速。** 最新测试与未通过范围见 [本轮记录](android-device-design.md) 和 [合成页耗时数据](android-synthetic-baseline-2026-10-08.json)。

手机 APK 随后在真实大麦详情页完成了节点、截图和 OCR 读取。诊断确认原 100 ms 节点遍历预算会在页面切换期间过早中止；调整为 500 ms 后，仍保留节点数量上限和不完整即停止。30 次热读取全部完成，OCR 中位 **346.5 ms**、P95 **414 ms**，USB 总往返中位 **650.09 ms**。结束后已停止录屏。该组不是进程冷启动，也不是与桌面同页交错测量；尚不能证明整体提速。详见 [手机真实详情页基线](android-phone-detail-baseline-2026-10-08.json)。真实场次票档、观演人、确认页和完整手机执行器仍未验收。调整版另通过合成危险页与锁屏停止检查，分别返回 `payment_foreground`、`screen_locked`；这不等于真实支付宝交接验收，也不代表已完成两小时稳定性验证。

## 10 月 8 日优化与验证

- 本地 Vision OCR 改为复用一个进程；截图仍仅通过内存传递。通讯读写有超时、长度和结果校验，异常时销毁进程，下次人工读取可重新启动。
- 已点击但页面仍加载时显示等待状态，继续核对结果，不误报终止，也不重复点击。场次已选中但票档尚未返回时，仍有有限等待窗口。
- 识别文本只有空格变化时，保留用户选择的票档和有效准备。执行开始后继续显示本次目标，并增加点击校验、执行总耗时。
- 手机上残留的读取组件，仅在确认没有相关服务运行且 SHA-256 与本地版本一致时复用，退出时保留原有文件。其他版本或正在使用的环境继续拒绝接管。

在同一张黎明郑州站预约页票档截图上交错测试 4 组，两个识别器的 16 条文字、置信度、坐标结果完全一致。排除各自首次调用后，旧单次进程用时为 426.3、294.1、304.1 ms；新复用进程为 156.5、142.5、164.9 ms，中位数分别为 **304.1 ms、156.5 ms**。这只是固定图像的 OCR 测试，不是下单速度或成功率。

最终桌面包在华为 SEA-AL10、大麦 9.0.35 上读取黎明郑州站预约页，识别 2026-11-21 周六 19:00 和 5 个票档，默认看台 588 元、1 张。返回正式详情后保留计划，读取 689 ms；随后预热 410 ms，其中读取 407 ms、命中 OCR 缓存，进入“演出已核对，等待开售”。自动提交保持关闭，没有启动执行或提交预约、订单。

**首次读取仍有冷启动开销**：这次最终包首次读取 14.68 秒，其中 OCR 12.24 秒。应在开售前启动、读取和预热；本次优化没有证明能消除首次初始化，也没有验证正式开售瞬间、持续捡漏或高峰排队。

Python 75 项、JavaScript 76 项、Rust 61 项检查通过，桌面构建成功；包内驱动、OCR 和页面适配资源与源文件一致。

## 开始前

- USB 连接华为 SEA-AL10，打开大麦 9.0.35，登录并保持解锁。
- 打开 Tickets 桌面应用的 **安卓真机工作台**。浏览器只能预览。
- 当前版本依赖这台 Mac 的 ADB、uv Python 缓存及 Swift 工具，不是可复制到其他电脑直接运行的独立发行包。
- 登录态留在手机，不需要填写 Cookie。观演人按默认前 N 人或自定义名单选择；程序不会猜测哪位是本人，也不修改证件信息。

## 读取与锁定

1. 手机打开演出详情或正式选票页，点 **自动读取演出与票档**。有正式购票入口时自动进入，读取场次，选择已选日期或首个可选日期并加载票档。
2. 核对下拉框中的 **场次、票档、张数**。更换日期会同步操作手机并自动更新票档；也可点 **重新读取票档**。不再需要手填日期和价格。
3. 默认选择已读取的唯一最低价，包括缺货票档。缺货会停止，不会自动换更贵的票；需要其他价位时，从下拉框明确选择。
4. 选择默认前 N 位或填写自定义观演人，再按需要勾选 **自定义：自动提交订单并跳转支付宝**，然后点 **锁定目标并预热**。
5. 等到 **目标已锁定**，核对右侧日期、票档、张数和观演人规则。更改目标、观演人名单或自动提交开关会使旧准备失效，必须重新锁定。

预约页只允许读取已有场次与票档作为计划，不会替你提交预约。读取到完整且已选中的场次信息后，回到正式演出详情重新读取，才可为尚未开售的演出准备待命。未读取完整的目标不能手填绕过；开售后仍需按正式选票页再次核对。预约页自动读取已实现，但本轮真机完整验收使用的是正式在售场次。

## 执行终点

- **未勾选自动提交**：推进至订单确认页，按规则选好观演人后暂停，由本人核对和提交。
- **勾选自动提交**：核对确认页的演出、日期、单价、总额、张数和目标观演人；总额不能超过所选单价乘张数。先完成默认或自定义观演人选择，再选择支付宝并只提交一次。检测到支付宝前台后立即结束自动操作，付款由本人完成。

观演人列表不完整、目标不可选、信息不匹配、未知弹窗或验证时暂停。不会反复提交；点击响应丢失或未能确认跳转，也会停止并提示检查手机订单状态。

选择 **立即执行**，或选择 **定时开始** 并填写未来 7 天内的北京时间。定时等待期间保持应用运行、大麦在手机前台；到点重新核对当前页面后操作。未开售时只读取等待，不点击预约、开售提醒或缺货登记。

**停止** 能阻止后续动作，不能撤回已经发出的提交或点击。切换工作台页面不会取消任务。断连、锁屏或异常不会自动恢复；需要重新读取和准备。默认执行期限 120 秒，最多 30 次动作。
