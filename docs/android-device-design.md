# 大麦安卓真机方案与验收记录

## 2026-10-09：现有桌面执行器的观演人选择

按用户要求，电脑 USB 购票流程新增默认前 N 人和自定义名单。`buyerLabels=[]` 表示按手机确认页完整名单顺序选前 N 人；非空名单表示逐一匹配准确姓名或“姓名 · 证件类型 · 脱敏号码”显示标识。名单和数量一起参与准备凭证匹配，改变名单后必须重新准备。

原生解析只接受已适配确认页中唯一的观演人列表、逐行姓名/类型/脱敏号码/勾选控件。列表缺失、滚动或裁切、重复标识、人数不足、目标不可用时停止。执行先取消非目标人，再逐一选择目标人，每步验证勾选结果；运行中名单或顺序改变时停止，避免索引指向另一个人。日志不记录姓名或号码，桌面仅在内存中保存名单，不新增证件存储。

无论是否自动提交，观演人点击前均核对演出、场次、单价、总额和张数。自动提交关闭时，完成勾选后停在确认页；开启时仍只提交一次并交给支付宝，由用户付款。手机验证 APK 未因此获得购票执行能力。

本次先新增失败回归再实现。Python 157 项、JavaScript 87 项、Rust 63 项通过；最终 macOS `.app` 构建成功，并完成本地 ad-hoc 签名及严格校验。浏览器预览检查了默认/自定义切换、两人名单输入和张数联动；预览结束后已关闭临时服务。新版桌面包位于 `src-tauri/target/release/bundle/macos/tickets.app`，已打开；根目录旧 `Tickets.app` 未替换。新增勾选尚未通过真机操作验收：只读检查时设备返回大麦非前台或锁屏，没有发送点击。本轮此前获授权的 880 元购票仅到达确认页，在未选择观演人时停止，未提交订单。

## 2026-10-08：手机验证与跨入口提交保护续作

本节是重构中的阶段记录。下方 10 月 3 日的真实订单操作仅保留为历史证据，**不构成本轮下单授权**；本轮没有发起真实订单提交或付款。

### 已落地的实现

- Android 可行性 APK 使用用户开启的无障碍服务、用户授权的系统录屏和随包中文 OCR。升级后的短码配对仅在手机回环地址监听，经 USB 转发使用；不绑定局域网、不公开部署。8 位码 120 秒有效、限 5 次有效格式失败尝试、一次性消费。重新生成/停止使待兑换码失效；已配对长密钥与进程同寿命，仍不支持购票执行。
- 桌面 Python 提交记录目录与 Tauri `app_data_dir()/android-submissions` 对齐。macOS 为 `~/Library/Application Support/com.tickets/android-submissions`，同时保守检查旧 `~/Library/Application Support/Tickets/android`；两处记录都加锁并持久化。补充双向 CLI/桌面阻止、旧账本损坏/冲突、部分写入、部分解除和进程竞争测试。
- Rust 与 Python 对人工确认的标识统一要求 32 位小写十六进制；前端要求用户明确核对订单后才能解除，且不会因停止或重启自动清除记录。
- `tools/android/companion_probe.py` 对齐手机实际协议、仅输出脱敏指标，并提供引导式短码配对和有界热读页采样。首次采样与热样本分开；USB 往返包含电脑转发和轮询，不能与手机原生处理耗时混算。

## 范围与使用流程

沿用 Vue 3 + Tauri + Rust 桌面架构。Mac 通过 USB ADB 连接华为 SEA-AL10，由 UIAutomator2 3.7.0 读取并操作官方大麦 9.0.35。登录态留在手机，安卓流程不使用 H5 建单接口或 Cookie。

用户点击“自动读取演出与票档”，工作台自动进入正式选票页、读取场次和对应票档；更改场次后自动读取新票档。不再接受手填目标。锁定和预热后，默认执行到确认页；勾选“自定义：自动提交订单并跳转支付宝”后继续核对并提交一次，到支付宝前台结束自动操作。观演人使用手机已选信息，付款由本人完成。

当前验收偏好为 **1 张、最低票档、本人**。界面默认选择读取到的唯一最低价，包括缺货票档；缺货时暂停，不能为继续流程而自动升档。价格相同但名称不同的多个最低票档不自动选定。

预约页可只读提取已选场次及票档并保存在同一设备、同一演出的内存候选目录中，但不允许在该页 prepare、start 或点击预约。返回正式详情后才能锁定待命，正式开售后仍需重新匹配。目录未完整读取时禁止准备。本版依赖当前 Mac 的 ADB、uv 缓存和 Swift 工具。

## 模块与协议

| 模块 | 文件 | 职责 |
| --- | --- | --- |
| 工作台 | `src/views/android.vue` | 连接、读取场次票档、锁定预热、立即或定时执行、停止和实测耗时 |
| 前端状态与校验 | `src/services/android.js`、`androidValidation.js` | 状态轮询、最低价选择、准备目标匹配、北京时间校验 |
| Rust 桥接 | `src-tauri/src/android.rs` | 固定 ADB 枚举、请求校验、JSONL 路由、驱动生命周期 |
| 手机驱动 | `tools/android/driver.py` | 单任务调度、准备凭证、当前页面读取、动作结果核对、取消 |
| 页面适配 | `tools/android/damai.py` | 原生结构与 OCR 候选、预约识别、可售状态、数量及下一步决策 |
| 本地 OCR | `tools/android/ocr.py`、`ocr.swift` | Apple Vision 文字识别及编译预热，不上传图片 |
| 图片区域缓存 | `tools/android/vision_cache.py` | 对当前原生区域像素生成缓存键，仅复用未变化区域的识别结果 |
| 只读诊断 | `tools/android/probe.py` | 连接、版本和可选节点读取，不包含购票动作 |

桌面与 Python 持久进程通过 stdin/stdout JSONL 通信，按 `requestId` 分发响应；不另开 HTTP 服务。外部命令以参数数组执行。驱动一次只执行一个手机任务，`status` 和 `stop` 不排在页面读取后等待。

| 请求 | 输入和前置条件 | 响应期限 |
| --- | --- | --- |
| `inspect` | `deviceId`；读取并清除旧准备结果 | 100 秒，允许首次工具准备 |
| `open_picker` | 已读取的设备及 `eventTitle`；明确正式购票入口 | 100 秒 |
| `select_session` | 已读取的设备、`eventTitle`、准确 `session`；确认选中后返回票档 | 100 秒 |
| `prepare` | 已读取设备与完整 `config`，`startAt` 为空；后台预热，按当前页生成完整核对或仅演出核对结果 | 15 秒内返回任务状态 |
| `start` | 同设备、完整 `config`、有效 `preparedId`；目标与准备结果一致 | 15 秒内返回任务状态 |
| `status` / `stop` | 查询内存状态 / 使本设备任务代次失效 | 8 秒 |

`ready` 为非活动状态，`preparing`、`waiting`、`running` 为活动状态。准备结果包含 `id`、`at`、`readiness`、`verification` 和不带有效开始时间的目标配置：

| 来源 | `readiness` / `verification` | 已核对内容与边界 |
| --- | --- | --- |
| 正式选票页，已完成选择 | `selected` / `full` | 演出、场次、票档和张数已核对并预选，停在确认页入口之前 |
| 正式选票页，目标明确未开售 | `waiting_sale` / `full` | 演出、场次、票档文字可完整核对，但不表示已选中或占有库存 |
| 正式详情页，明确为 `upcoming` | `waiting_sale` / `event_only` | 仅核对演出并预热；从此前页面读取的计划场次、票档尚未在正式选票页验证，正式开放后逐项匹配 |

`event_only` 必须显示“演出已核对并预热；场次和票档待开售后逐项核对，不一致即停止”，不能显示成完整目标已核对或已预选。预约页、未知页面和不明确的详情状态不产生该结果。

启动必须携带准备凭证，并再次核对演出、场次、票档、张数；启动时消耗凭证。停止、重新读取、切换场次及异常会清除或使准备结果失效，目标修改需要重新准备。状态中的 `phase`、`prepared` 和 `metrics` 由 Rust 完整透传；驱动重启不会恢复旧任务。

打包应用使用自身 Resources 中的 Python、Swift 资源，以应用缓存目录 `android-runtime` 作为进程工作目录，避免依赖桌面源码路径。退出先关闭 stdin，给 Python 清理设备服务的机会，超时后再结束本次子进程组。

## 读取与性能路径

旧实现每步读取页面后，在点击前再完整读取一次；单次读取又包含设备枚举、shell 前台查询、PNG 截图与 OCR，并在动作后固定等待 0.7 秒。新版按以下顺序减少不必要工作：

1. **复用连接，使用原生 RPC。** 已连接设备不逐次枚举；通过 `device.info` 读取当前包与屏幕状态，替代每次 shell `app_current` 查询。UIAutomator 页面树仍是识别结构与边界的依据。
2. **先识别页面，再决定是否需要图片。** 原生节点足以确认的订单确认页不截图或 OCR；预约页有场次、票档容器时才补充 OCR；Canvas 自绘场次、票档及按钮用 JSON-RPC JPEG 截图补充文字和选中边框。
3. **按区域像素缓存 OCR。** 依据当前原生容器边界选择场次、票档和按钮区域，缓存键包含图片尺寸、区域位置与这些区域的像素摘要。最多保留 8 组内存结果；文字、价格、选中状态或位置变化会重新识别。未纳入摘要的区域文字不会进入缓存。
4. **共享刚读取的当前帧。** 仅复用驱动自身刚返回、同一任务代次且距原生树读取不超过 400 毫秒的页面对象。超过期限或不是该对象则重新读取；准备凭证不携带供之后盲点的旧坐标。
5. **把预热移到准备阶段。** `prepare` 先准备本地 OCR 可执行文件。正式选票页继续核对、预选，停在确认页入口前；明确未开售的详情页只核对演出，生成 `event_only` 待命结果。正式执行不重复启动预热流程。首次读取自绘页面仍可能需要编译 OCR，不能承诺所有首次读取都很快。
6. **按动作效果等待，去掉固定 0.7 秒。** 点击场次或票档后必须看到目标选中；增减数量后必须看到恰好变化一张；打开选票或进入确认后必须看到相应页面转移。无关区域变化不算点击成功。结果未确认时短暂读取等待，超过窗口暂停，不连续重复点击。

`metrics` 记录 `readMs`、`treeMs`、`screenshotMs`、`ocrMs`、`cacheHit`，以及准备与执行的 `prepareMs`、`triggerLagMs`、`firstActionMs`。这些是当前采样，不能直接推算平台受理速度、库存或成功率。

Swift 首次编译到 `~/Library/Caches/tickets-android-ocr/`，按源码、系统与架构区分编译缓存。OCR 图片通过内存和 stdin 传递，原始节点和截图默认不落盘、不上传；图片缓存仅在当前 Python 进程内存在。

## 页面和点击边界

- 先依据大麦包名、原生资源 ID、父子关系识别页面，再在对应卡片范围内匹配 OCR 文字。目标必须唯一；边界来自当前控件，不使用通用固定坐标。
- “预约想看场次 / 预约想看票档”优先识别为预约页，不能被同名场次容器误认成购票页。详情入口要求明确购票文案；空白、未知、预约、提醒或缺货文案不产生购票点击目标。
- 选票页可先只有场次。切换场次后，必须确认目标场次选中并读取该场票档，不能把旧场次还未消失的票档当作切换成功。
- 选中状态结合原生标记与当前截图边框。明确未开售只等待；缺货或不可选暂停，不预约、不登记、不升档。
- 未开售详情待命不对场次或票档作已验证声明。开放后进入正式选票页仍按配置逐项严格匹配，不以预约页文字或准备凭证跳过核对。
- 数量只读取 `layout_sku_num_ll` 内唯一 `tv_num` 的“1张”等文字，使用同容器内唯一且可用的 `img_jia` / `img_jian` 单步调整，不能从库存或促销数字猜数量。
- 任务代次在读取、更新和点击前后检查。失去连接或前台、出现验证、弹窗、未知页面或目标歧义即停止或转人工；无法确认点击响应时不自动重试。已经发出的单次点击无法撤回。
- 默认执行期限 120 秒，最多 30 次动作；读取返回后及发动作前再次检查期限。短暂页面转场允许在受限窗口内只读等待，不扩大成无限重试。
- 默认确认页停止；`autoSubmit=true` 时确认页核对演出、日期、单价、总额、张数与已选观演人数，选择支付宝后只提交一次。该选项参与准备配置匹配，不能在启动时偷换。支付宝仅在本次已提交之后允许作为交接前台；不读取支付控件、不点击付款。`needs_action` 不等于已支付或出票。

## 复现检查

从项目根目录执行离线检查，不连接或操作手机：

```sh
uv run --offline --no-project --with uiautomator2==3.7.0 python -B -m unittest discover -s tools/android -p 'test_*.py' -v
npm test
cargo test --manifest-path src-tauri/Cargo.toml --lib
```

`python3 tools/android/probe.py` 只检查连接与版本；`uv run tools/android/probe.py --ui` 会临时启动页面读取、不会点击。后者遇到已有 UIAutomator 服务或 `u2.jar` 时拒绝覆盖，不能与桌面手机任务同时运行。缓存缺失需先准备运行环境，不能把本地工具启动问题归因于手机授权。
