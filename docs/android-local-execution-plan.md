## 顺序、交付和验收

1. **本地固定目标到确认页**：增加与 Android 分离的执行状态机、限时动作与效果校验；接入手机无障碍原生快照和精确控件点击；提供手机本地配置/开始/停止入口。执行明确禁止确认页任何点击和自动提交。配置、等时、读页、决策、点击均在手机本地；桌面只作配对/状态/停止。未知/自绘布局不能假装适配完成，需逐项列出真实设备阻塞。
2. **触摸证据**：独立核对 minitouch 固定来源、Android API29/华为限制和已安装依赖；受控测试只操作本应用合成按钮。分别计量派发耗时与可观察效果耗时，预热和交错顺序、成功率、超时及样本数必须报告。不可用后端记录原因，不用零耗时替代样本，也不以官方注释推导实测速度。
3. **优先/备选/等待**：授权目标按顺序，预算和数量为硬边界；优先窗口结束后才启用备选。库存等待有截止时间及退避；重复本地读页不是主动刷新成功。没有已验证刷新入口时仅报告被动观察，不能宣称持续捡漏已经接通。
4. **生命周期**：手动停止、锁屏、无障碍失效、非大麦前台、未知/登录/验证页、截止时间均禁止后续点击；进程重启不自动恢复。动作代次和当前树验证防止延迟点击。此增量不提供提交动作，因此不改变既有提交账本；完整跨电脑/手机提交互斥通过前禁止打开手机自动提交。

## 尚未关闭的代码审查项（交付前必须修复并回归）

- 节点 `refresh()` 在派发锁内执行，可能阻塞停止并使点击前检查过期。移出锁，在真正点击前复核代次、截止时间、锁屏和前台。
- 无障碍事件的包过滤可能漏掉等待期内短暂切到其他应用再返回。需要接收跨应用窗口事件，但仍只遍历授权的大麦内容。
- 禁用缺货等待时，多目标可见备选分支仍可能点击。先执行禁用等待的停止判断，并覆盖两目标用例。
- 同场次的可见备选优化可能跳过更高优先级的其他场次。必须按授权顺序检查，增加跨场次三目标回归。

这些问题来自只读审查，当前没有据此宣称已修复；正常手机仍未安装本地执行预览版。
